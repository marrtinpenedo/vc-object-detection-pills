## Snapshot de ejecución

El despliegue histórico usa el descriptor `8d479bfd14b079057f12d94fee5e3d412a3b0905ea114f39509695965f0ef170`. El tar archivado conserva los 20 archivos que certifica ese descriptor. Si se modifica el código, `python3 -m scripts.campaign --exp008 bundle RUTA_NUEVA.tar.gz` genera otro snapshot. Usar un directorio de código y una raíz de resultados separados para cada ejecución.

Desde la raíz del repositorio en el portátil, verificar el archivo y transferir únicamente el código de ejecución junto con su SHA-256:

```bash
(
  set -euo pipefail
  evidence=experiments/exp-008-cascade-freezing/results/evidence
  (cd "$evidence" && sha256sum -c SHA256SUMS)
  mkdir -p results
  (cd "$evidence" && sha256sum exp-008-cascade-freezing.tar.gz) \
    > results/exp-008-cascade-freezing.tar.gz.sha256
  scp "$evidence/exp-008-cascade-freezing.tar.gz" \
    results/exp-008-cascade-freezing.tar.gz.sha256 USUARIO_CESGA@ft3.cesga.es:
)
```

Una ejecución nueva se puede enviar desde el login de CESGA con una raíz de resultados propia:

```bash
(
  set -euo pipefail
  cd "$HOME"
  sha256sum -c exp-008-cascade-freezing.tar.gz.sha256
  mkdir "$HOME/pills-exp008-repro"
  tar -xzf exp-008-cascade-freezing.tar.gz -C "$HOME/pills-exp008-repro"
  bash "$HOME/pills-exp008-repro/slurm/campaign.sh" exp008 launch \
    --root "$STORE/pills-baseline/results/exp-008-repro"
)
```

El lanzador utiliza `$STORE/pills-baseline` con su entorno `envs/cascade`, datos preparados y pesos COCO. Para otra ubicación, definir `PILLS_CAMPAIGN_WORK` y especificar la raíz de resultados con `--root`. El lanzamiento histórico usó la raíz predeterminada `results/exp-008-freezing` dentro del árbol de trabajo. La campaña usa una A100 por trabajo. El preflight comprueba Detectron2 0.6, los pesos COCO y el backward del control. Su smoke de tres pasos verifica la transición de ResNet en el segundo paso. Cada entrenamiento depende del preflight y cada evaluación de su propio entrenamiento.

## Estado y recuperación

Desde el directorio de código usado en CESGA, consultar la campaña histórica o sustituir la raíz de resultados por la usada en una reproducción:

```bash
root="$STORE/pills-baseline/results/exp-008-freezing"
bash slurm/campaign.sh exp008 status --root "$root"
bash slurm/campaign.sh exp008 collect "$HOME/exp008-results-recuperado.tar.gz" --root "$root"
```

Si queda un intento fallido, inspeccionar `jobs.json`, `logs/` y `sacct -j ID --format=JobID,JobName,State,ExitCode,Elapsed`. Para reintentarlo bajo el mismo snapshot, usar `bash slurm/campaign.sh exp008 launch --retry-failed --root "$root"`. Si falta un ID tras el envío, cotejar el nombre exacto con SLURM y registrar el trabajo con `bash slurm/campaign.sh exp008 reconcile NODO --job-id ID --root "$root"`. Usar `--confirmed-not-submitted` solo si SLURM confirma que nunca se envió. Los reintentos conservan intentos activos y completados. Un entrenamiento fallido se reinicia desde COCO en otro directorio de intento. Una evaluación fallida puede reutilizar su entrenamiento completado.

El exportador escribe en un destino nuevo y conserva predicciones, PR, historiales, huellas y auditorías. Los checkpoints y los datos permanecen en su ubicación original. La [guía de análisis local](../../experiments/exp-008-cascade-freezing/results/evidence/README.md#reproducción-local) permite analizar tanto una exportación recuperada como la evidencia del repositorio.
